📘 Resumen Paso a Paso hasta como usar Git
  • Instalación: Descargaste Git Bash para Windows y verificaste la instalación usando el comando git --version.
  • Configuración Inicial: Definiste tu nombre, correo y la rama principal "main" mediante comandos git config --global. Revisaste todo con git config --list.
  • Inicialización: Creaste la carpeta GIT en VS Code y ejecutaste git init, lo que generó la carpeta oculta .git para guardar el historial y los commits.
  • Archivos sin seguimiento: Creaste un archivo y aprendiste que la letra "U" significa Untracked (detectado pero no seguido por Git).
  • Flujo de Trabajo: El flujo se compone de tres áreas consecutivas: Working Directory (edición), Staging Area (preparación con git add .) y Repository (guardado con git commit).
  • Primer Guardado: Usaste git add . para preparar los archivos y git commit -m "Primer commit" para crear una captura o snapshot del proyecto.
  • Control de Estado: Aprendiste a usar git status para ver el estado general y git diff para comparar líneas modificadas antes de confirmar un cambio. Al hacer el commit, estas herramientas se limpian.
  • Integración en VS Code: La pestaña Source Control replica de forma visual las funciones de status, diff, add (+) y commit.
  • El Ciclo Profesional: La rutina recomendada es: Modificar → status → diff → add → commit.
  • Próximos Pasos: Una vez dominado este ciclo, sigue aprender: git log, git restore, el archivo .gitignore, ramas (branches), fusiones (merge) y la plataforma GitHub (push/pull).

Como usar GIT restore

Es una herramienta diseñada exclusivamente para restaurar archivos a un estado previo (generalmente al estado del último commit). Funciona como un "Ctrl + Z" inteligente para tu código.

Que es HEAD y Hash

El HEAD es un puntero simbólico que indica cuál es tu posición actual en el historial de Git. Es el equivalente al indicador de "usted está aquí" en un mapa. Por lo general, apunta a la rama en la que estás trabajando (como main), la cual a su vez apunta al último commit de esa rama. Al mover el HEAD, cambiás lo que ves en tu editor de código.

Un Hash (o SHA-1) es el identificador único universal de cada commit. Es una cadena de 40 caracteres alfanuméricos que Git genera automáticamente mediante un algoritmo matemático basándose en el contenido de los archivos, el autor, la fecha y el mensaje del commit. Funciona como la huella digital exacta de ese momento de tu proyecto.

Volver a commit anterior GIT checkout

Cuando usás git checkout <hash>, básicamente le estás diciendo a Git: "Por favor, mové mi HEAD (mi puntero actual) a este punto del pasado".

El concepto de "Detached HEAD"

Antes de hacerlo, tenés que conocer este concepto clave. Cuando te movés a un commit pasado, entrás en un estado llamado "Detached HEAD".

¿Qué significa y cuáles son sus riesgos?
  • ¿Qué significa? Que el HEAD ya no está pegado a tu rama (main), está "desconectado" y flotando en el pasado.
  • ¿Es peligroso? No, siempre y cuando sepas que todo lo que hagas ahí es temporal.
  • Riesgo de pérdida: Si hacés cambios y te vas a otra rama sin guardarlos, esos cambios se perderán.
