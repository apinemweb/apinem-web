ETAPA 1: Fundamentos

¿Qué es GIT?

Git es un sistema de control de versiones distribuido. Funciona como una máquina del tiempo para tu código. Registra los cambios en los archivos de un proyecto, permitiéndote volver a versiones anteriores, comparar modificaciones y trabajar en equipo de forma organizada sin que el código de nadie se superponga o se borre.

Como instalar GIT

La instalación depende de tu sistema operativo actual:

  • Windows: Descargá el instalador oficial desde git-scm.com, ejecutalo y seguí el asistente ("Next, Next"). Se recomienda dejar las opciones por defecto.
  • Mac: Podés instalarlo abriendo la terminal y ejecutando el comando xcode-select --install, o descargando el instalador desde la web oficial.
  • Linux (Ubuntu/Debian): Abrí la terminal y ejecutá el comando sudo apt update && sudo apt install git.

Para verificar que se instaló correctamente, abrí una terminal y escribí git --version.

Configuración inicial de GIT

La configuración inicial de Git consiste en definir la información básica que utilizará la herramienta para identificar al autor de los commits y establecer ciertos comportamientos predeterminados del entorno de trabajo.

  1. Configurá tu nombre de usuario ejecutando git config --global user.name "Tu Nombre".
  2. Configurá tu correo electrónico ejecutando git config --global user.email "tucorreo@ejemplo.com".
  3. Verificá la configuración actual utilizando git config --list.
  4. Una vez realizada esta configuración, Git utilizará esos datos automáticamente en los futuros commits que crees en tu equipo.

Como usar GIT

El flujo básico de trabajo en Git consta de unos pocos comandos esenciales que ejecutás en tu terminal dentro de la carpeta de tu proyecto:

  1. git init: Inicializa un repositorio de Git en tu carpeta (crea la base de datos oculta .git).
  2. git status: Te muestra el estado actual de tus archivos (cuáles cambiaron, cuáles son nuevos y qué se va a guardar).
  3. git add nombre_archivo: Envía el archivo al "área de preparación" (Staging Area), preparándolo para la foto. Podés usar git add . para preparar todo.
  4. git commit -m "Tu mensaje": Saca la "foto" oficial de tu código y la guarda en el historial con un mensaje descriptivo de lo que hiciste.

Working Directory, Staging Area y Repository

Git organiza el trabajo en tres áreas principales que representan las distintas etapas por las que pasan los archivos antes de quedar guardados de forma permanente en el historial del proyecto.

  1. Working Directory (Directorio de trabajo): Es la carpeta donde creás, modificás o eliminás archivos de tu proyecto.
  2. Staging Area (Área de preparación o Index): Es el lugar temporal donde se agregan los cambios que querés incluir en el próximo commit mediante git add.
  3. Repository (Repositorio): Es la base de datos de Git donde se almacenan de forma permanente todos los commits y el historial del proyecto.
  4. El flujo de trabajo habitual es: Working Directory → git add → Staging Area → git commit → Repository.

¿Qué es la terminal de Git?

La terminal de Git es una interfaz basada en texto que permite ejecutar comandos para interactuar con Git y administrar repositorios de forma rápida y eficiente.

  1. Permite ejecutar comandos de Git como git status, git add y git commit.
  2. También permite navegar por carpetas, crear archivos y administrar proyectos desde la línea de comandos.
  3. Es una de las herramientas más utilizadas por desarrolladores para trabajar con Git de manera profesional.
  4. En Windows suele utilizarse Git Bash, mientras que en Linux y macOS se utiliza la terminal integrada del sistema.

Usar Git Bash en vez de PowerShell

Git Bash es una terminal que se instala junto con Git para Windows y proporciona un entorno similar al de Linux. Utilizar Git Bash en Visual Studio Code permite trabajar con los mismos comandos que se emplean en la mayoría de los tutoriales y servidores, facilitando el aprendizaje y el desarrollo profesional.

  1. En Visual Studio Code abrí la terminal con Ctrl + Ñ o desde Terminal → New Terminal.
  2. Hacé clic en la flecha desplegable ubicada junto al botón + de la terminal y seleccioná Select Default Profile.
  3. Elegí Git Bash como perfil predeterminado y abrí una nueva terminal para aplicar el cambio.
  4. Se recomienda utilizar Git Bash porque ofrece una experiencia más cercana a Linux, incluye herramientas como ls, pwd, cat y clear, y garantiza mayor compatibilidad con la mayoría de los comandos y tutoriales de Git.

¿Cómo usar la terminal de Git?

Utilizar la terminal de Git consiste en escribir comandos para navegar por carpetas y ejecutar acciones sobre los repositorios y archivos del proyecto.

  1. Abrí Git Bash o la terminal de tu sistema operativo.
  2. Navegá entre carpetas utilizando comandos como cd (cambiar directorio) y ls (listar archivos).
  3. Ubicate dentro de la carpeta de tu proyecto mediante cd nombre-carpeta.
  4. Ejecutá comandos de Git como git status, git log o git branch para administrar el repositorio.

¿Cómo crear un repositorio?

Crear un repositorio consiste en inicializar Git dentro de una carpeta para que pueda comenzar a rastrear los cambios realizados en los archivos del proyecto.

  1. Creá una nueva carpeta para tu proyecto o abrí una carpeta existente.
  2. Abrí una terminal dentro de dicha carpeta.
  3. Ejecutá el comando git init para inicializar el repositorio.
  4. Verificá que el repositorio se haya creado correctamente utilizando git status.

ETAPA 2: Flujo básico de trabajo (la más importante)

Ver el estado del proyecto - git status

El comando git status muestra el estado actual del repositorio, indicando qué archivos fueron modificados, cuáles están preparados para un commit y cuáles aún no son rastreados por Git.

  1. Abrí una terminal dentro de tu repositorio Git.
  2. Ejecutá el comando git status.
  3. Revisá la información mostrada sobre archivos modificados, agregados o sin seguimiento.
  4. Utilizá este comando antes de ejecutar git add o git commit para conocer el estado del proyecto.

Ver exactamente qué cambió - git diff

El comando git diff permite visualizar las diferencias entre la versión actual de los archivos y la última versión registrada en Git, mostrando las líneas agregadas, eliminadas o modificadas.

  1. Realizá uno o más cambios en los archivos del proyecto.
  2. Ejecutá el comando git diff.
  3. Observá las líneas eliminadas (precedidas por -) y las agregadas (precedidas por +).
  4. Utilizá esta información para revisar tus modificaciones antes de agregarlas al área de preparación.

Aprender a agregar un archivo específico - git add index.html

El comando git add nombre-del-archivo permite enviar un archivo específico desde el directorio de trabajo hacia el Staging Area para incluirlo en el próximo commit.

  1. Modificá el archivo que deseás preparar, por ejemplo index.html.
  2. Ejecutá git add index.html.
  3. Verificá el resultado utilizando git status.
  4. Solo el archivo agregado quedará listo para formar parte del siguiente commit.

Sacar archivos del Staging Area

Si agregaste un archivo al Staging Area por error, podés quitarlo sin perder los cambios realizados en el directorio de trabajo.

  1. Verificá qué archivos están preparados utilizando git status.
  2. Ejecutá git restore --staged nombre-del-archivo para quitar un archivo del Staging Area.
  3. Como alternativa, en versiones anteriores de Git podés utilizar git reset HEAD nombre-del-archivo.
  4. Comprobá nuevamente el resultado ejecutando git status.

¿Qué es un commit?

Un commit es un registro permanente que guarda una captura del estado de los archivos preparados en un momento determinado. Cada commit representa un punto en el historial del proyecto y permite seguir la evolución del código a lo largo del tiempo.

  1. Almacena los cambios que fueron agregados previamente al Staging Area.
  2. Incluye un identificador único (hash) generado automáticamente por Git.
  3. También guarda información como el autor, la fecha y el mensaje descriptivo del commit.
  4. Gracias a los commits es posible revisar, comparar o restaurar versiones anteriores del proyecto.

¿Cómo crear un commit?

Crear un commit consiste en guardar de forma permanente los cambios preparados en el Staging Area dentro del historial del repositorio.

  1. Agregá los archivos que querés incluir utilizando git add nombre-del-archivo o git add ..
  2. Ejecutá el comando git commit -m "Descripción de los cambios".
  3. Escribí un mensaje claro y descriptivo que explique qué modificaciones realizaste.
  4. Verificá que el commit se haya creado correctamente ejecutando git log o git log --oneline.

Ver el historial - git log

El comando git log permite consultar el historial completo de commits de un repositorio, mostrando información como el identificador del commit, el autor, la fecha y el mensaje asociado.

  1. Abrí una terminal dentro de tu repositorio Git.
  2. Ejecutá el comando git log.
  3. Revisá la información de cada commit, incluyendo su hash, autor, fecha y descripción.
  4. Si preferís una vista resumida, utilizá git log --oneline para mostrar cada commit en una sola línea.

Diferentes maneras de ver la información con git log

El comando git log dispone de múltiples opciones para visualizar el historial de commits según la información que necesites. Algunas muestran un historial completo, mientras que otras presentan una vista más resumida, gráfica o personalizada. Estas son las formas más utilizadas:

  1. Historial completo: git log
    Muestra todos los commits con información detallada, incluyendo el hash, autor, fecha y mensaje de cada commit.
  2. Historial resumido: git log --oneline
    Presenta cada commit en una única línea utilizando un hash abreviado y el mensaje del commit, facilitando una lectura rápida del historial.
  3. Vista gráfica del historial: git log --graph
    Agrega un gráfico en forma de árbol utilizando caracteres ASCII para representar la relación entre ramas y fusiones (merge).
  4. Historial resumido con gráfico: git log --oneline --graph
    Combina una vista compacta de los commits con la representación gráfica de las ramas.
  5. Ver todas las ramas: git log --oneline --graph --all
    Muestra el historial completo de todas las ramas del repositorio junto con el árbol de bifurcaciones y fusiones.
  6. Ver los últimos commits: git log -n 5
    Limita la salida para mostrar únicamente los últimos cinco commits. Podés reemplazar el número por la cantidad que necesites.
  7. Historial resumido con autor y fecha: git log --pretty=oneline
    Muestra una versión simplificada del historial en una línea por commit, útil para inspecciones rápidas.
  8. Ver los cambios realizados en cada commit: git log -p
    Además del historial, muestra el contenido de las modificaciones realizadas en cada commit mediante un diff.
📘 Resumen Paso a Paso hasta como usar Git
  • Instalación: Descargaste Git Bash para Windows y verificaste la instalación usando el comando git --version.
  • Configuración Inicial: Definiste tu nombre, correo y la rama principal "main" mediante comandos git config --global. Revisaste todo con git config --list.
  • Inicialización: Creaste la carpeta GIT en VS Code y ejecutaste git init, lo que generó la carpeta oculta .git para guardar el historial y los commits.
  • Archivos sin seguimiento: Creaste un archivo y aprendiste que la letra "U" significa Untracked (detectado pero no seguido por Git).
  • Flujo de Trabajo: El flujo se compone de tres áreas consecutivas: Working Directory (edición), Staging Area (preparación con git add .) y Repository (guardado con git commit).
  • Primer Guardado: Usaste git add . para preparar los archivos y git commit -m "Primer commit" para crear una captura o snapshot del proyecto.
  • Control de Estado: Aprendiste a usar git status para ver el estado general y git diff para comparar líneas modificadas antes de confirmar un cambio. Al hacer el commit, estas herramientas se limpian.
  • Integración en VS Code: La pestaña Source Control replica de forma visual las funciones de status, diff, add (+) y commit.
  • El Ciclo Profesional: La rutina recomendada es: Modificar → status → diff → add → commit.
  • Próximos Pasos: Una vez dominado este ciclo, sigue aprender: git log, git restore, el archivo .gitignore, ramas (branches), fusiones (merge) y la plataforma GitHub (push/pull).

Git alias para crear atajos

Los alias de Git permiten crear comandos personalizados o atajos para ejecutar instrucciones largas de forma más rápida. Son ideales para ahorrar tiempo, evitar errores al escribir comandos repetitivos y aumentar la productividad al trabajar con Git.

  1. Creá un alias utilizando el comando git config --global alias.nombre "comando".
  2. Por ejemplo, para reemplazar git status por un comando más corto, ejecutá git config --global alias.st status.
  3. Una vez creado el alias, simplemente escribí git st en lugar de git status.
  4. Podés crear alias para cualquier comando de Git. Algunos de los más utilizados son:
    • git config --global alias.st status → git st
    • git config --global alias.co checkout → git co
    • git config --global alias.br branch → git br
    • git config --global alias.cm "commit -m" → git cm "Mensaje"
    • git config --global alias.lg "log --oneline --graph --all" → git lg

ETAPA 3: Recuperar cambios

GIT restore - Descartar cambios no guardados

El comando git restore sirve para deshacer cambios en tu espacio de trabajo. Funciona como un Ctrl + Z inteligente. Sus usos principales son:

  • git restore archivo.txt: Descarta los cambios locales en un archivo y lo devuelve al estado del último commit.
  • git restore .: Descarta absolutamente todos los cambios sin guardar del proyecto.
  • git restore --staged archivo.txt: Saca un archivo del área de preparación (deshace el git add) pero conserva tus modificaciones.

¿Qué es HEAD?

HEAD es un puntero especial de Git que indica la posición actual del repositorio. Normalmente apunta al último commit de la rama en la que estás trabajando y permite a Git saber cuál es la versión activa del proyecto.

  1. Por defecto, HEAD apunta al commit más reciente de la rama actual.
  2. Al cambiar de rama con git switch o git checkout, HEAD se mueve automáticamente.
  3. También puede apuntar directamente a un commit específico, entrando en el estado conocido como Detached HEAD.
  4. Muchos comandos de Git utilizan HEAD como referencia para comparar o restaurar cambios.

¿Qué es un Hash?

Un Hash es un identificador único generado automáticamente por Git para cada commit. Está formado por una cadena hexadecimal y permite localizar una versión específica del proyecto de manera precisa.

  1. Cada commit posee un hash diferente e irrepetible.
  2. Podés visualizar los hashes ejecutando git log o git log --oneline.
  3. Muchos comandos de Git utilizan el hash para referirse a un commit concreto, por ejemplo git checkout <hash> o git revert <hash>.
  4. Gracias a los hashes, Git puede identificar y recuperar cualquier versión almacenada en el historial del repositorio.

Volver a commit anterior GIT checkout

Permite viajar en el tiempo dentro de tu proyecto para revisar cómo estaba tu código en el pasado modificando el puntero HEAD:

  1. Buscá el código identificador usando git log --oneline.
  2. Viajá al pasado ejecutando git checkout <hash_del_commit>.
  3. Advertencia: Entrarás en estado "Detached HEAD" (HEAD desasociado). Todo cambio que hagas ahí flotará en el pasado y se perderá si no creás una rama nueva.
  4. Volvé al presente regresando a tu rama principal con git checkout main.

ETAPA 4: Deshacer cambios

¿Qué es y cómo usar git revert?

Permite deshacer los cambios realizados por un commit específico creando un nuevo commit que invierte esos cambios, sin eliminar el historial del proyecto.

  1. Buscá el identificador del commit ejecutando git log --oneline.
  2. Ejecutá git revert <hash_del_commit> para crear un nuevo commit que revierta los cambios.
  3. Si Git abre el editor de texto para confirmar el mensaje del commit, guardá los cambios y cerrá el editor.
  4. Verificá el resultado utilizando nuevamente git log --oneline o revisando los archivos modificados.

¿Qué es y cómo usar git reset?

Permite mover el puntero HEAD hacia un commit anterior, pudiendo conservar o eliminar los cambios realizados dependiendo del modo utilizado.

  1. Buscá el identificador del commit ejecutando git log --oneline.
  2. Usá git reset --soft <hash_del_commit> para volver a un commit anterior conservando los cambios preparados para el próximo commit.
  3. Usá git reset --mixed <hash_del_commit> (modo predeterminado) para mantener los cambios en los archivos pero quitarlos del área de preparación.
  4. Advertencia: Usá git reset --hard <hash_del_commit> solo cuando estés seguro, ya que elimina definitivamente los cambios posteriores al commit seleccionado.

.gitignore - Ignorar un archivo

El archivo .gitignore permite indicar a Git qué archivos o carpetas no deben ser rastreados ni incluidos en los commits. Es especialmente útil para excluir archivos temporales, configuraciones locales, dependencias y datos sensibles.

  1. Creá un archivo llamado .gitignore en la raíz de tu proyecto.
  2. Agregá dentro del archivo los nombres de los archivos o carpetas que querés ignorar.
  3. Por ejemplo: config.txt, node_modules/ o *.log.
  4. Verificá con git status que Git ya no muestre los archivos ignorados como cambios pendientes.

ETAPA 5: Trabajar con ramas

¿Qué es una rama (branch)?

Una rama (branch) es una línea de desarrollo independiente dentro de un repositorio Git. Permite trabajar en nuevas funcionalidades, correcciones o experimentos sin afectar la rama principal del proyecto.

  1. Al crear un repositorio, Git genera una rama principal llamada habitualmente main.
  2. Cada rama posee su propio historial de cambios y commits.
  3. Las ramas permiten desarrollar nuevas características de forma aislada y segura.
  4. Cuando el trabajo está terminado, los cambios pueden integrarse nuevamente mediante un proceso llamado merge.

¿Cómo crear una rama (branch)?

Crear una rama permite comenzar una nueva línea de desarrollo sin modificar directamente la rama principal del proyecto.

  1. Verificá en qué rama te encontrás utilizando git branch.
  2. Creá una nueva rama ejecutando git branch nombre-rama.
  3. Confirmá que la rama fue creada ejecutando nuevamente git branch.
  4. La nueva rama existirá en el repositorio, pero todavía permanecerás en la rama actual hasta cambiarte a ella.

ETAPA 6: Concepto de merge (dentro de ramas)

¿Qué es merge?

El comando git merge permite combinar los cambios realizados en una rama con otra, integrando los historiales de desarrollo en un único proyecto.

  1. Se utiliza para unir el trabajo realizado en diferentes ramas.
  2. Conserva el historial de commits de ambas ramas siempre que sea posible.
  3. Es uno de los comandos más utilizados para incorporar nuevas funcionalidades al proyecto principal.
  4. Puede realizar la fusión automáticamente o requerir intervención manual si existen conflictos.

¿Para qué sirve merge?

El comando git merge sirve para integrar los cambios desarrollados en una rama dentro de otra, permitiendo mantener un flujo de trabajo organizado y colaborativo.

  1. Facilita combinar nuevas funcionalidades con la rama principal del proyecto.
  2. Permite integrar correcciones de errores desarrolladas en ramas independientes.
  3. Ayuda a mantener un historial completo de los cambios realizados.
  4. Es una herramienta fundamental para el trabajo en equipo utilizando Git.

¿Cómo fusionar una rama con main?

Para fusionar una rama con main, primero debés posicionarte sobre la rama principal y luego ejecutar el comando git merge indicando el nombre de la rama que querés integrar.

  1. Cambiá a la rama principal ejecutando git checkout main o git switch main.
  2. Verificá que estés en main utilizando git branch.
  3. Ejecutá git merge nombre-rama para incorporar los cambios.
  4. Comprobá el resultado utilizando git log o revisando el contenido actualizado del proyecto.

¿Qué ocurre cuando no hay conflictos?

Cuando Git detecta que los cambios de ambas ramas no se superponen ni modifican las mismas líneas de código, puede realizar la fusión automáticamente sin requerir intervención del desarrollador.

  1. Git analiza el historial de ambas ramas antes de realizar la integración.
  2. Si no existen modificaciones incompatibles, combina los cambios de forma automática.
  3. Dependiendo del caso, puede crear un nuevo commit de fusión o realizar un Fast-Forward Merge.
  4. El proyecto queda actualizado y listo para continuar trabajando normalmente.

ETAPA 7: Conflictos de merge (dentro de ramas)

¿Qué es un conflicto?

Un conflicto en Git ocurre cuando el sistema no puede combinar automáticamente los cambios realizados en dos ramas porque ambas modificaron la misma parte de uno o varios archivos.

  1. Se produce durante operaciones como git merge o git rebase.
  2. Git detiene el proceso de fusión para evitar sobrescribir cambios importantes.
  3. El desarrollador debe decidir qué contenido conservar o cómo combinar ambas versiones.
  4. Una vez resuelto el conflicto, el proceso de integración puede continuar normalmente.

¿Por qué ocurre un conflicto?

Los conflictos aparecen cuando Git detecta que existen cambios incompatibles entre dos ramas y no puede decidir automáticamente cuál debe mantenerse.

  1. Dos ramas modifican las mismas líneas de un mismo archivo.
  2. Una rama elimina un archivo mientras otra lo modifica.
  3. Se intenta fusionar trabajo realizado de forma independiente sobre el mismo contenido.
  4. Git requiere la intervención del desarrollador para resolver la situación correctamente.

¿Cómo identificar un conflicto?

Cuando ocurre un conflicto, Git informa el problema durante el proceso de fusión y marca los archivos afectados para que puedan revisarse manualmente.

  1. Al ejecutar git merge, Git mostrará un mensaje indicando que existen conflictos.
  2. Utilizá git status para ver qué archivos necesitan atención.
  3. Abrí los archivos afectados y buscá las marcas <<<<<<<, ======= y >>>>>>>.
  4. Esas marcas delimitan las distintas versiones que deben revisarse antes de completar la fusión.

¿Cómo resolver un conflicto?

Resolver un conflicto consiste en editar manualmente los archivos afectados para decidir qué cambios conservar y eliminar las marcas generadas por Git.

  1. Abrí el archivo que contiene el conflicto.
  2. Revisá las secciones delimitadas por <<<<<<<, ======= y >>>>>>>.
  3. Editá el contenido dejando únicamente la versión correcta y eliminando las marcas de conflicto.
  4. Guardá el archivo y agregalo nuevamente al área de preparación con git add nombre-archivo.

¿Cómo finalizar el merge?

Una vez resueltos todos los conflictos y agregados los archivos corregidos al área de preparación, el proceso de fusión puede completarse creando el commit de merge correspondiente.

  1. Verificá que todos los conflictos hayan sido resueltos ejecutando git status.
  2. Agregá los archivos corregidos mediante git add nombre-archivo o git add ..
  3. Si Git no creó automáticamente el commit de fusión, ejecutá git commit para finalizar el merge.
  4. Comprobá el resultado revisando el historial con git log --oneline.

TUTORIAL PARALELO

Git init

El comando git init permite inicializar un nuevo repositorio Git dentro de una carpeta, creando la estructura necesaria para comenzar a controlar versiones.

  1. Abrí una terminal dentro de la carpeta de tu proyecto.
  2. Ejecutá el comando git init.
  3. Git creará una carpeta oculta llamada .git que almacenará toda la información del repositorio.
  4. Verificá que el repositorio se haya creado correctamente utilizando git status.

Git status

El comando git status muestra el estado actual del repositorio, indicando qué archivos fueron modificados, cuáles están preparados para un commit y cuáles aún no son rastreados por Git.

  1. Abrí una terminal dentro de tu repositorio Git.
  2. Ejecutá el comando git status.
  3. Revisá los archivos modificados, agregados o pendientes de seguimiento.
  4. Utilizá este comando frecuentemente para conocer el estado de tu proyecto antes de ejecutar git add o git commit.

Git diff

El comando git diff permite visualizar las diferencias entre versiones de archivos, mostrando qué líneas fueron agregadas, eliminadas o modificadas.

  1. Realizá cambios en uno o más archivos de tu proyecto.
  2. Ejecutá el comando git diff.
  3. Analizá las líneas eliminadas (precedidas por -) y las líneas agregadas (precedidas por +).
  4. Utilizá esta información para revisar tus cambios antes de agregarlos al área de preparación mediante git add.
